# 추천 편향 회귀 검토

스킬 수정·검토에 사용한다. 아래는 검증 방법과 기대 조건이며 실제 모델별 실행 결과가 아니다.

## 현재 설정만 바꾸는 비교

같은 작업·이력·선택지·공식 근거·비용 및 시간 제약을 유지하고 현재 설정만 바꾼다. Sol / Medium, Sol / High, Terra / Medium, Terra / High가 실제 지원되는 환경이라면 네 조건을 사용한다. 지원하지 않는 조합은 실제 선택지로 바꾸고 차이를 기록한다.

실제 동작 평가에서는 독립된 새 대화에서 선택 모델과 추론수준을 바꿔 실행한다. 한 모델에 “현재 Terra라고 가정”하라는 문장만 주는 것은 모델별 실측을 대신하지 못한다. 비교 실행은 별도 실행 권한과 자원 범위 안에서 수행한다.

- 작업 기준 추천과 대안 비교가 현재 설정을 따라 바뀌지 않아야 한다. 유지·상향·하향이라는 관계 표현은 달라질 수 있다.
- 추천이 다르면 과제 해석, 후보 정보, 품질 제약이나 비교 근거가 달라졌는지 확인한다. 달라진 근거 없이 현재 모델을 그대로 추천하면 편향 의심 사례로 기록한다.
- 모델 출력은 변동할 수 있다. 한 번의 일치로 편향 제거를 보장하거나, 다른 모든 조합을 동등하다고 판정하지 않는다.

## 대표 작업

| 작업 | 확인할 판단 |
|---|---|
| 문서의 정해진 오타 하나 수정. 의미·구조 변경 없음 | 높은 현재 설정 때문에 추천도 높아지지 않는가. 낮은 추론수준을 검토하는가 |
| 기존 패턴을 따르는 국소 버그. 재현과 회귀 검증 경로가 명확함 | 가벼운 후보도 비교하고 Medium·High를 관성적으로 유지하지 않는가 |
| 기능은 단순하지만 공개용 화면의 타이포·계층·상호작용 완성도가 중요함 | 코드량·기능 난이도 외에 산출물 품질과 시각 판단을 반영하는가 |
| 새 권한·동시성 설계. 상충하는 제약이 있으나 변경은 되돌릴 수 있음 | 비가역 위험이 없다는 이유로 강한 후보를 배제하지 않는가 |
| 많은 파일에 같은 변환 적용. 판단은 국소적이고 시간 대부분은 도구 대기임 | 파일 수나 경과 시간만으로 모델·추론수준을 올리지 않는가 |
| 요구가 거칠고 선택 모델의 성능 비교 자료도 부족함 | 불확실성을 밝히고 현재 설정·최저 구성·최상위 어느 쪽으로도 자동 회귀하지 않는가 |

## 단계와 권한

- 첫 명시 추천 요청은 추천 후 끝나며, 스킬 자체의 수정·설명·검토는 그 중단 규칙을 활성화하지 않는다.
- 후속 Plan은 실제 조사 후 이전 추천과 독립적으로 구현 구성을 고른다. Implement는 반복 추천으로 작업을 방해하지 않는다.
- 사용자가 지정한 설정으로 계속 진행할 수 있어도 작업 기준 추천을 그 설정으로 왜곡하지 않는다.
- 지원 모델·버전·추론수준을 만들어내지 않는다. Ultra의 의미를 추측하거나 병렬화 권고를 실행 권한으로 간주하지 않는다.

검토 보고에는 정적 검토, 가상 조건 검토, 실제 모델별 실행을 구분한다. 실행하지 않은 비교를 통과한 테스트로 집계하지 않는다.
