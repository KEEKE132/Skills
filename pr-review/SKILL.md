# PR Review

주어진 Pull Request의 변경사항을 분석하고, 개발자가 PR의 내용을 이해하고 검토할 수 있도록 정리한다.

## Guidelines

* PR 리뷰나 리뷰 코멘트를 직접 등록하지 않는다.
* PR의 변경사항과 목적을 파악하고 개발자가 이해하기 쉽게 설명한다.
* 기존 프로젝트의 아키텍처, 구조, 패턴, 컨벤션을 유지하고 있는지 확인한다.
* PR의 목적과 관계없는 불필요한 변경이 포함되어 있는지 확인한다.
* 변경 범위가 필요 이상으로 다른 도메인이나 책임까지 확장되어 있는지 확인한다.
* 코드, 설계, 동작, 구조 측면에서 개발자가 확인해야 할 리뷰 항목을 찾는다.
* 리뷰 항목에 적절한 해결 방법이 있다면 권장안을 설명하고, 필요한 경우 다른 대안과 차이점도 함께 제시한다.
* 각 리뷰 항목에 번호를 붙여 추가 지시하기 편하게 한다.
* 일반적인 모범 사례를 일괄 적용하기보다 기존 프로젝트의 구조와 맥락을 기준으로 판단한다.
* 리뷰 과정에서 코드를 직접 수정하지 않는다.
* 각 리뷰 항목에 중요성에 따라 [P1~P3] 태그를 붙인다.
* 각 리뷰는 하나의 리뷰에 각각 인라인 리뷰로 적절한 코드에 작성한다, 만약 적절한 코드가 없거나 전반에 관한 이야기라면 리뷰 본문에 작성한다.

## Output

분석 결과를 보기 쉬운 Markdown 문서로 정리하여 `.md` 파일로 저장한다.

문서에는 PR의 특성에 따라 다음 내용을 포함한다.

* PR의 목적과 주요 변경사항
* 주요 구현 내용과 영향 범위
* 기존 아키텍처 및 컨벤션과의 일관성
* 불필요하거나 과도하게 확장된 변경사항
* 개발자가 확인해야 할 리뷰 항목
* 리뷰 항목에 대한 권장 해결안 및 대안
* 각 리뷰 항목에 대한 추천 human-like 리뷰 메세지 (너무 세세하거나 strict 하지 않을 것)

고정된 형식을 강제하지 않고 PR의 규모와 변경 구조에 맞게 문서를 구성한다.
