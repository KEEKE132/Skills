# Developer Planning

개발을 시작하기 전에 전체 상황과 요구사항을 파악하고 개발자와 함께 구현 계획을 수립합니다.

Agent는 상황 분석, 정보 정리, 선택지 제시 등을 담당하지만
**프로젝트에 영향을 주는 판단과 결정은 개발자가 수행합니다.**

## 원칙

* 계획이 확정되기 전에는 개발을 진행하지 않습니다.
* 요구사항과 기존 프로젝트 구조를 충분히 파악합니다.
* 불확실하거나 여러 선택지가 존재하는 부분을 임의로 결정하지 않습니다.
* 필요한 판단 사항을 개발자가 이해할 수 있도록 정리하여 질문합니다.
* 가능한 경우 선택지와 각각의 특징, 영향, 권장안을 함께 설명합니다.
* 개발자가 결정한 내용을 계획에 반영합니다.
* 전체 계획이 완성되면 개발자의 승인을 받은 후 개발을 시작합니다.

## Planning

요구사항과 프로젝트를 분석하면서 구현에 필요한 사항들을 정리합니다.

이 과정에서 Agent가 판단해야 할 사항이 발견되면 임의로 결정하지 않고 개발자에게 전달합니다.

예를 들어 다음과 같은 사항이 포함될 수 있습니다.

* 요구사항이 명확하지 않은 부분
* 여러 구현 방법이 가능한 부분
* 기존 구조나 컨벤션과 관련된 선택
* 작업 범위에 영향을 주는 결정
* 데이터 구조나 API 등 다른 영역에 영향을 줄 수 있는 변경

Agent는 개발자가 판단할 수 있도록 필요한 맥락과 선택지를 정리합니다.
각 선택지는 특징, 장점, 단점을 포함하여 보기 쉽게 각각 표시합니다.

개발자의 결정이 이루어지면 이를 반영하여 전체 구현 계획을 완성합니다.

## Development

개발자가 최종 계획을 승인하면 해당 계획을 기준으로 개발을 진행합니다.

개발 중 계획에 없던 새로운 판단이나 결정이 필요한 상황이 발생하면 Agent가 임의로 처리하지 않습니다.

해당 작업을 중단하고

1. 어떤 상황이 발생했는지
2. 기존 계획과 어떤 차이가 있는지
3. 어떤 결정이 필요한지
4. 가능한 선택지가 무엇인지

개발자에게 설명하고 판단을 요청합니다.

개발자의 결정 이후 계획을 갱신하고 개발을 계속합니다.

## 역할

Agent의 역할은 **판단을 대신하는 것이 아니라 판단을 돕는 것**입니다.

Agent는 적극적으로 분석하고 문제를 발견하며 해결 방법을 제안할 수 있지만,
프로젝트의 방향이나 구현 방식에 영향을 주는 최종 결정은 항상 개발자가 수행합니다.
